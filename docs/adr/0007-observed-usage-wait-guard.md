# ADR 0007: Shape the lead wait guard from observed session usage

The lead's shell wait guard is a pure text classifier over the first segment of a bash command, split on `;`, `&&`, `||` and newlines. It refuses a sleep-only wait while owned work runs and a leading sleep of 30 seconds or more at any time, and nothing else. Both rules and the threshold come from a scan of real lead and child sessions recorded in [#187](https://github.com/taekwondodev/dev/issues/187), where every leading long sleep lasted 45 to 270 seconds and every shorter leading sleep was a brief pause before a check the user chose to keep allowed. The first rule was accepted in [#145](https://github.com/taekwondodev/dev/issues/145).

Shapes the classifier does not read are accepted gaps, not defects: a redirect, pipe or comment after the duration, an environment or wrapper prefix such as `time` or `timeout`, a subshell, a leading comment line, a long sleep after the first step, and foreground polling loops. Background `&` is deliberately allowed because the observed usages were legitimate and the reported case ran its background work on a remote host where no local guard could see it. Closing these gaps speculatively would turn the guard into a general shell-loop detector, which the work guide rules out, and would block legitimate commands that no session has shown to be a problem.

Extend the contract only from real usage: a new refused shape, a different threshold or a child-side rule needs occurrences in actual sessions, retrieved and cited the way #187 does, that show the agent blocking its turn in that shape. A hypothetical bypass found by reading the classifier is not sufficient evidence.

Read this record before changing the wait guard's classifier, threshold, refusal messages or the set of agents it applies to.
