# ADR 0006: Keep the visual layer in global extensions, tuned to Ghostty

Presentation changes to Pi's interface, such as the footer, live in global extensions under `~/.pi/agent/extensions/`, not in dev and not in Pi's code. They apply to plain `pi` and to dev alike, and survive Pi upgrades without patches. They target the one terminal in use, Ghostty with JetBrainsMono Nerd Font Mono, and use its private-use glyphs without a fallback: the user chose a richer interface over portability, accepting placeholder boxes in any other terminal or font.

Dev publishes one event on Pi's event bus, `dev/work-view`: the complete view of a session's current children, running local commands and blocking notices. Each emission replaces the previous one, so subscribers keep only the latest view and no state of their own, and dev keeps no second registry of children for them. Dev owns which children belong to the view. It supplies facts only, with no formatting or status text, emits nothing without a UI and does not depend on a subscriber. Live facts, such as a child's turn count and current activity, travel from the child to the controller and to the view without ever being persisted. Transcript renderers read the `details` of `work` results and outcome messages, never model-visible `content`.

Extensions adapt to dev, never the reverse: when dev changes `content`, `details` or an event, the global extensions change with it and dev keeps no field for their sake. A typed stream of change events was rejected: it would put a fold in every subscriber and solve a late-subscriber case that does not occur, because disk extensions load before dev's own and `/reload` closes work.

Read this record before adding presentation to dev, making dev depend on a specific extension, changing the `dev/work-view` contract, or supporting another terminal or font.
