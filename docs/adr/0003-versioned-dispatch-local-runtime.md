# ADR 0003: Version dispatch and keep private runtime data local

Version a default dispatch with the implementation and resolve it from the installed module, independently of the working project and data home. The default names no model, so any installation runs with its own Pi default. Each owner's model policy is personal configuration: a file in the installation's Git-ignored profiles directory replaces the default as a whole, so updates neither overwrite it nor are blocked by it. Keep private runtime state in checkout-local, Git-ignored `.dev/` by default; data-home overrides change private storage only. This makes clones reproduce dispatch rules without distributing one owner's model choice, history or credentials, and lets code updates change the default without moving private data. Invalid dispatch, including an invalid personal file, must fail explicitly rather than silently substitute a model policy.

Authentication is account-wide: Pi, dev and its children share the [Pi credential store](../../SECURITY.md#credentials), independently of data-home overrides. Keeping one canonical credential store avoids copies drifting apart when the user logs in from either environment.

Workspace ownership is the narrow exception to checkout-local runtime storage. The [approved authority](https://github.com/taekwondodev/dev/issues/31#issuecomment-5798717688) uses the OS-account location in the [state map](../launcher.md#state), independent of `HOME`, installation location or a data-home override. All installations must discover the same reservations and stable gates, otherwise changing data home could admit competing writers. Managed worktrees live under that authority; existing checkouts, Pi conversations, credentials and other profiles are not relocated. Initial support is local, non-synchronized macOS storage, not multi-machine coordination.

Sources: [dispatch and storage](https://github.com/taekwondodev/dev/issues/12#issuecomment-5730822083), [shared authentication](https://github.com/taekwondodev/dev/commit/9e7feb3ca51e3835c2f6800e2591c540567b42b0). Read this record before changing storage scope or dispatch ownership; use [private-state relocation](../DEVELOPMENT.md#private-state-relocation) for moves and [maintenance admission](../launcher.md#maintenance) for revision changes.
